# CSS 架构重构设计

## 背景

当前前端样式由 `src/index.css` 导入 8 个全局 CSS 文件，共 4,376 行、约 93 KB，包含 567 条规则和 2,521 个声明。其中 `chat.css`、`modals.css` 和 `sidebar.css` 占总行数约 69%。现有代码还有 97 个 `!important`、34 个 `transition: all`、125 个位于主题 token 之外的硬编码颜色，以及已经没有首方调用的旧控件样式。

最近一次样式拆分将原有单文件机械拆成模块，但没有改变全局级联、重复控件或覆盖链。后续功能仍通过追加业务选择器和提高优先级完成，因此文件边界没有真正成为样式职责边界。

## 目标

- 在保留全部内容、功能、交互流程、深浅主题和密集日志阅读体验的前提下，彻底重建样式职责边界。
- 将 CSS 总量降到 2,600 行以内，将声明数降到 1,750 个以内。
- 将 `!important` 降到 16 个以内，并只允许用于第三方样式覆盖和强制隐藏工具。
- 消除首方硬编码颜色、废弃选择器和 `transition: all`。
- 允许统一间距、色阶、阴影、圆角和动画，并接受明显但克制的视觉简化。
- 不引入 UI 框架、CSS-in-JS、预处理器或运行时样式系统。

## 非目标

- 不改变扫描、导入、SSH 同步、会话选择、筛选、时间轴、导出、复制、收藏、标签或主题切换等产品行为。
- 不重写 TypeScript UI 架构，也不改变 store 或 parser 契约。
- 不追求重现重构前的逐像素截图；截图用于发现溢出、遮挡、缺失和不可用状态。
- 不通过压缩格式、删除所有空行或引入大量原子工具类来虚增行数成果。

## 样式架构

`src/index.css` 只负责声明 cascade layer 顺序并导入下列模块：

1. `tokens.css`：深浅主题颜色、间距、排版、圆角、阴影、层级和动画 token。
2. `base.css`：reset、全局元素默认值和页面基础排版。
3. `primitives.css`：button、icon button、input、textarea、chip、badge、dropdown、panel、modal 等基础控件。
4. `layout.css`：应用外壳、顶部栏、侧栏和时间轴的主要布局及响应式规则。
5. `sidebar.css`、`session.css`、`dialogs.css`、`content.css`：只包含各业务区域的布局、状态和内容呈现。
6. `vendor.css`：Highlight.js、KaTeX、Mermaid 及其他第三方生成 DOM 的样式和必要覆盖。
7. `utilities.css`：只包含 `.hidden` 等少数全局工具。

级联顺序固定为 tokens、base、primitives、layout、features、vendor、utilities。业务模块不能重新声明完整基础控件，只能组合基础类、设置组件级 CSS 变量或增加业务状态样式。第三方选择器不得散落在业务模块中。

## DOM 与类名策略

现有业务类继续承担 JavaScript 查询、测试定位和业务布局语义，避免把行为迁移与视觉迁移绑在一起。需要共享视觉的元素增加低耦合的 `ui-*` 基础类，例如 `ui-button`、`ui-icon-button`、`ui-input`、`ui-chip`、`ui-badge`、`ui-menu` 和 `ui-panel`。

业务类只负责组件特有的尺寸、位置或状态。例如 `.header-fav-btn` 保留收藏行为语义，但通用按钮结构来自 `.ui-icon-button`；`.filter-pill` 保留 SSH source 筛选语义，但通用 pill 结构来自 `.ui-chip`。现有 `.active`、`.open`、`.visible` 等状态类继续由当前事件逻辑管理，不在本次重构中改写状态模型。

## Token 与主题

主题仍由 `html[data-theme="dark"]` 控制。所有首方颜色都在 `tokens.css` 定义，业务模块不得直接使用十六进制或 `rgb()`/`rgba()` 值。来源、收藏、固定和状态颜色各自只定义一个主色，弱背景和边框通过 `color-mix()` 派生，从而删除逐来源、逐主题重复选择器。

Token 收敛为实际使用的集合。删除未使用变量、重复字体别名和历史 fallback。间距以 4 px 为基础，只保留常用档位；控件只保留紧凑和标准两种高度；圆角只保留控件、面板和 full 三档；阴影只保留浮层和模态框两档；动画只允许按属性声明，不允许 `transition: all`。

## 视觉简化

- 保留 `DESIGN.md` 规定的黑白基调和主区域 mesh gradient，删除其他装饰性渐变、玻璃拟态、发光和过度阴影。
- 面板和日志条目使用平面背景、单层边框和稳定的信息密度；hover 不再通过缩放或位移制造层级。
- 按钮、输入框、筛选项、标签和徽章统一高度、圆角、字体与 focus ring。
- 下拉菜单和模态框是唯一常规使用阴影的首方组件。
- 来源、角色和状态仍可通过颜色区分，但使用统一的色彩派生规则，不维护独立的明暗主题样式块。
- 响应式规则收敛为桌面和窄屏两个主要层级；仅在实际布局需要时保留额外断点，不允许业务文件各自新增近似断点。
- 删除描述历史调整、营销式形容词和已经失效的实现注释，只保留解释约束或非显然兼容性的注释。

## 数据流与容错

主题数据流保持为根元素属性 → token → 基础组件 → 业务变体。TypeScript 只组合类名和现有状态，不生成内联主题值或运行时 stylesheet。

若业务组件无法直接采用基础类，优先通过组件级 CSS 变量调整；不得复制整套控件声明。若第三方库需要高优先级覆盖，规则必须位于 `vendor.css`，每个 `!important` 都要附带具体原因。浏览器不支持的实验性语法不进入首方关键路径；本项目已经使用的 `color-mix()` 和 `:has()` 可继续使用。

## 迁移顺序

1. 建立 CSS 架构测试、token、cascade layers 和基础组件，不删除旧业务规则。
2. 迁移顶部栏、应用外壳、侧栏和时间轴，并删除对应旧基础声明。
3. 迁移会话正文、Markdown、代码块、工具调用、引用、图片和通知卡片。
4. 迁移模态框、表单、下拉菜单、toast 和导出界面。
5. 将 Highlight.js、KaTeX 和 Mermaid 规则移入 `vendor.css`，删除旧选择器和临时覆盖。
6. 运行最终 CSS 指标审计，继续合并重复规则直到满足量化目标。

每一步先迁移 DOM 类组合，再删除被替代规则，并运行相关 DOM 测试。若某一步出现回归，可以按组件族回退，而不需要恢复整套旧样式。

## 测试与验收

新增 `tests/css-architecture.test.ts`，直接读取样式文件并约束模块导入、总行数、声明数、`!important` 数量、`transition: all`、首方硬编码颜色和明确废弃的选择器。测试不依赖新增第三方解析库。

更新现有 UI 测试，验证关键元素获得正确的 `ui-*` 基础类，并继续覆盖点击、展开、筛选、复制、导出和 modal 等行为。只有在类名本身属于现有行为契约时才保留原断言；纯视觉类断言改为检查基础组件职责。

重构前后使用仓库现有截图工具生成本地对照，覆盖深浅主题、桌面和窄屏、侧栏抽屉与固定状态、时间轴、主要模态框、下拉菜单、代码块、工具调用、图片、Mermaid 和空状态。视觉差异本身不是失败，但内容缺失、不可读、溢出、遮挡、错误层级、不可见 focus、不可操作控件或移动端横向滚动属于失败。

最终必须通过：

- `npm run test`
- `npm run typecheck`
- `npm run build`
- CSS 总量不超过 2,600 行
- CSS 声明数不超过 1,750 个
- `!important` 不超过 16 个
- `transition: all` 为 0
- `tokens.css` 和 `vendor.css` 之外的首方硬编码颜色为 0
- 已确认废弃的首方选择器为 0

## 风险与控制

- 基础类抽取可能意外改变组合选择器优先级。Cascade layers 固定层级，迁移按组件族进行，并在删除旧规则前验证实际 DOM。
- 深浅主题色统一派生会产生预期内的视觉变化。以可读性和状态区分为验收标准，不恢复逐组件主题补丁。
- 第三方库生成 DOM 的类名不一定出现在首方源码中。废弃选择器审计必须区分首方动态类和 vendor 类，不能根据简单字符串扫描删除第三方规则。
- CSS 行数目标可能诱导不可读的压缩写法。验收同时检查声明数、规则职责和模块边界，禁止通过单行化或大范围逗号选择器掩盖复杂度。
